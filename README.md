# Виталий | Готовый бизнес — инструкция

Сайт построен на **Astro + TypeScript + Tailwind CSS**, редактируется через
**Decap CMS** и публикуется на **GitHub Pages**. Ниже — всё, что нужно, чтобы
опубликовать сайт и дальше вести его самостоятельно, без программирования.

---

## 1. Структура проекта

```
├── astro.config.mjs        # адрес сайта, интеграции (Tailwind, sitemap)
├── tailwind.config.mjs     # цвета, шрифты, анимации
├── src/
│   ├── content/             # ВСЁ содержимое сайта (редактируется через CMS)
│   │   ├── settings/main.yaml   # тексты и фото первого экрана, "Обо мне", контакты
│   │   ├── objects/<slug>/index.md + фото   # объекты (карточки бизнеса)
│   │   ├── faq/<slug>.md        # вопросы-ответы
│   │   └── videos/<slug>.md     # три видео блока "Как проходит работа"
│   ├── components/          # блоки страницы (код, трогать не нужно)
│   ├── layouts/BaseLayout.astro  # SEO/шапка HTML, схемы Schema.org
│   └── pages/index.astro     # вся страница целиком (сайт одностраничный)
├── public/
│   ├── admin/                # панель управления Decap CMS (/admin)
│   ├── robots.txt
│   └── og-cover.jpg          # картинка для соцсетей — замените на свою
└── .github/workflows/deploy.yml  # автопубликация на GitHub Pages
```

Все фотографии-заглушки внутри `src/content/**` подписаны как `PLACEHOLDER` —
их нужно заменить на настоящие через CMS (см. ниже) перед запуском.

## 2. Публикация на GitHub Pages

1. Создайте новый репозиторий на GitHub и загрузите туда содержимое этой папки
   (кроме `node_modules`, если он вдруг появится — он и так в `.gitignore`).
2. В `astro.config.mjs` замените `SITE_URL` на реальный адрес:
   - если сайт будет на `username.github.io` (репозиторий называется
     `username.github.io`) — оставьте `base` закомментированным;
   - если сайт будет на `username.github.io/repo-name` — раскомментируйте
     строку `base: BASE` и впишите `/repo-name`.
3. Тот же адрес пропишите в `public/admin/config.yml` (`site_url`,
   `display_url`) и в `public/robots.txt` (строка `Sitemap:`).
4. В настройках репозитория: **Settings → Pages → Source → GitHub Actions**.
   Публикация запустится автоматически по workflow `.github/workflows/deploy.yml`
   при каждом push в ветку `main` — ничего дополнительно нажимать не нужно.
5. Через 1–2 минуты после push сайт появится по адресу из шага 2.

## 3. Как войти в панель управления (CMS)

Сайт полностью статический (без сервера), поэтому для входа в CMS без
программирования используется бесплатный **Netlify** — но только как «служба
пропусков» (авторизация), сам сайт при этом продолжает работать на GitHub
Pages.

**Настройка один раз:**

1. Зарегистрируйтесь на [netlify.com](https://www.netlify.com) (бесплатно).
2. **Add new site → Import an existing project** → подключите тот же GitHub-
   репозиторий. Настройки сборки не важны, можно даже оставить пустыми и не
   давать Netlify публиковать сайт — этот Netlify-сайт нужен только для входа.
3. В настройках Netlify-сайта: **Identity → Enable Identity**.
4. Там же: **Identity → Services → Git Gateway → Enable Git Gateway**
   (Netlify сам получит доступ к вашему GitHub-репозиторию).
5. **Identity → Invite users** → отправьте приглашение на свою почту, перейдите
   по ссылке из письма и задайте пароль.

**Дальше вход в CMS:**

Откройте `https://ваш-сайт.github.io/admin/` → «Login with Netlify Identity» →
введите почту и пароль. Панель откроется на русском языке.

## 4. Как изменить тексты и фото на главной странице

В CMS откройте **Настройки сайта → Основные тексты и фото**. Там редактируются:

- фото и заголовок первого экрана;
- фото и текст блока «Обо мне»;
- телефон, WhatsApp, Telegram;
- пять карточек блока «Почему мне доверяют».

Нажмите **Save** (сохранить) — черновик сохранится, затем нажмите
**Publish** (опубликовать), чтобы изменения ушли на сайт. Публикация занимает
1–2 минуты.

---

## 5. Как добавить новое видео

В CMS откройте **Видео («Как проходит работа»)** → **New Video**.

- **Название** — подпись под видео.
- **Роль ролика** — выберите «Кто такой Виталий» / «Работа с покупателями» /
  «Работа с продавцами» (или «Другое», если добавляете видео сверх основных
  трёх — на сайте отображаются все видео из этого раздела).
- **Ссылка на видео** — вставьте ссылку на YouTube, RuTube, VK Видео или
  прямую ссылку на файл `.mp4`.
- **Обложка (превью)** — фото, которое показывается до нажатия на play.

Сохраните и опубликуйте.

---

## 6. Как добавить новый объект (бизнес на продажу)

В CMS откройте **Объекты** → **New Object**.

Заполните: название, отрасль, цену, город, обложку (превью для видео),
ссылку на видео и короткое описание.

**Ссылка на видео** принимает:
- VK Клип/Видео — вставьте обычную ссылку вида `https://vk.ru/clip-238886261_456239092`,
  сайт сам соберёт из неё нужный embed-адрес;
- YouTube — обычная ссылка на видео;
- прямая ссылка на файл `.mp4`.

Поле **«Порядок отображения»** управляет очерёдностью карточек — чем меньше
число, тем выше карточка. Видео на сайте открывается прямо внутри карточки по
клику — отдельной страницы у объекта нет (сайт одностраничный).

---

## 7. Как отметить объект «Продано»

Откройте нужный объект в CMS → включите переключатель **«Продано»** → Save →
Publish. На карточке появится диагональная печать «ПРОДАНО», фото станет
чёрно-белым.

---

## 8. Как изменить фотографии

Везде, где есть поле с картинкой (обложка объекта, фото в шапке, обложка
видео), нажмите на неё в CMS и загрузите новый файл — он автоматически
подставится вместо старого. Отдельно на GitHub ничего загружать не нужно.

---

## 9. Как изменить любые другие тексты

- Тексты первого экрана, «Обо мне», контакты, карточки доверия — раздел
  **«Настройки сайта»** (см. пункт 4).
- Вопросы и ответы (FAQ) — раздел **«Вопросы и ответы»**: можно добавлять,
  редактировать и менять порядок вопросов.
- Текст обзора конкретного бизнеса — внутри самого объекта, поле **«Полный
  текст обзора»**.

---

## 10. Локальный запуск (для разработчика)

```bash
npm install
npm run dev       # http://localhost:4321
npm run build     # проверка сборки перед публикацией, результат в dist/
```

## Что уже сделано сверх исходного ТЗ

Ниже — решения, которые я добавил сам, чтобы сайт лучше работал на конверсию,
скорость и удобство сопровождения, не меняя саму идею личного бренда.

1. **Приём заявок без сервера.** Три формы («Подобрать бизнес», «Продать
   бизнес», «Обратный звонок») отправляют готовое сообщение прямо в WhatsApp —
   это надёжнее почтовых форм на статическом хостинге и совпадает с тем, как
   аудитория и так планирует связываться.
2. **Видео с RuTube и VK, не только YouTube.** Форма ссылки на видео принимает
   любую платформу — на случай проблем с доступом к YouTube у части
   аудитории в России.
3. **Плеер загружается по клику (click-to-load).** Видео не грузится, пока
   пользователь сам не нажмёт play — это то, что обычно и «съедает» скорость
   на сайтах с видео; так PageSpeed остаётся высоким.
4. **Фирменный визуальный приём — печать «ПРОДАНО».** Вместо баннера или
   плашки — стилизованная сургучная печать под углом, в цвет фирменного акцента,
   она же логика самого бизнеса «сделка закрыта».
5. **Тёплая латунная палитра вместо типового тёмного + неонового акцента.**
   Отсылка к миру документов и сделок (латунь, сургуч), а не к дефолтному
   «дорогому тёмному сайту».
6. **Автоматические Schema.org-разметки**: Person, LocalBusiness, VideoObject
   через сами видео, FAQPage и BreadcrumbList на страницах объектов — без
   ручного заполнения, они формируются из содержимого CMS.
7. **Автопубликация через GitHub Actions** — после Publish в CMS сайт
   обновляется сам, отдельно нажимать «собрать сайт» не нужно.
8. **Уважение к системным настройкам** — анимации отключаются, если у
   посетителя включён режим «уменьшить движение» в системе.

## Что стоит сделать до запуска

- Заменить все фото-заглушки (подписаны `PLACEHOLDER`) на настоящие фото
  Виталия и объектов через CMS.
- Заменить ссылки-заглушки на видео на реальные ссылки.
- Проверить телефон/WhatsApp/Telegram в «Настройках сайта».
- Вписать реальный адрес сайта в `astro.config.mjs`, `public/admin/config.yml`
  и `public/robots.txt` (см. раздел 2).
